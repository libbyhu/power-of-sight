# 02 資料庫設計

資料表定義在 `backend/src/main/resources/db/migration/V1__init.sql`，由 Flyway 在啟動時建立。
同一份 SQL 可在 H2（PostgreSQL 相容模式）與 PostgreSQL 執行。

## 關係

```
users 1 ── 1 rooms            每位會員一間書房（註冊時自動建立）
users 1 ── * entries          會員的收藏
entries * ── 1 media_items    收藏指向一部作品
```

為什麼把「作品」和「收藏」分開？
`media_items` 是作品本身（書名、作者），`entries` 是「某人 × 某作品」的個人紀錄（喜好、備註）。
現在每筆作品都由新增它的人建立；之後接外部搜尋（Google Books、TMDB）時，多位會員可以共用同一部作品，不必改資料表。

## users

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | uuid | 主鍵 |
| email | varchar(254) | 唯一，存小寫 |
| password_hash | varchar(100) | BCrypt 雜湊，不存明碼 |
| display_name | varchar(40) | |
| created_at | timestamptz | |

## rooms

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | uuid | 主鍵 |
| owner_id | uuid | → users，唯一（一人一間） |
| name | varchar(60) | 預設「{名字}的書房」 |
| intro | varchar(500) | 選填 |
| quote_text / quote_source | varchar(200) / (100) | 書房的一句話，選填 |
| is_public | boolean | 預設 false。**公開參觀尚未開放**，目前沒有 API 可以改它 |
| created_at / updated_at | timestamptz | |

## media_items

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | uuid | 主鍵 |
| type | varchar(10) | BOOK / MOVIE / TV / ANIME |
| title | varchar(200) | 必填 |
| original_title | varchar(200) | 原文名稱，選填 |
| creator | varchar(120) | 作者／導演／創作者／工作室，依 type 顯示不同標籤 |
| release_year | integer | 1000–3000 |
| cover_url | varchar(500) | 必須是 http(s) 網址 |
| external_source / external_id | | 預留給外部搜尋 |
| created_by | uuid | → users |

第七版把作者、導演、工作室分在四張 detail 表。v8 合併成一個 `creator` 欄位：混放的書房裡搜尋「村上」或「宮崎駿」只需要查一欄，畫面也只需要依種類換標籤。

## entries

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | uuid | 主鍵 |
| owner_id | uuid | → users。所有查詢都會加上 `owner_id = 目前會員` |
| media_item_id | uuid | → media_items |
| status | varchar(12) | WANT / IN_PROGRESS / COMPLETED / ABANDONED，**可為 null** |
| preference | integer | 1–5，選填 |
| review | varchar(300) | 選填；介面上顯示為「備註」 |
| completed_on | date | 不能是未來日期 |
| display_order | bigint | 新增時 = 目前最大值 + 1。列表依此由大到小排；預留給之後的手動排序 |
| version | bigint | 樂觀鎖 |

索引：`(owner_id, display_order)` 給書房列表、`(owner_id, status)` 給狀態篩選。

## Migration 紀錄

| 版本 | 內容 |
|---|---|
| V1 | 建立 users、rooms、media_items、entries |
| V2 | rooms 新增 `layout_style`（書房擺放風格） |
| V3 | 移除 `layout_style`：擺放風格的設計取消，書房只保留一種呈現方式 |

已執行過的 migration 檔不修改；取消的功能以新的版本移除，讓每個環境的資料庫都能依序升級。

## 兩種「鎖」

- **悲觀鎖（新增時）**：`RoomRepository.lockByOwnerId` 會鎖住書房那一列，同一個人同時送出兩筆新增，第二筆要等第一筆完成，才不會拿到相同的 `display_order`。
- **樂觀鎖（修改時）**：前端修改要帶 `version`。後端比對不一致就回 409，不會讓舊畫面蓋掉新資料。

## 切換到 PostgreSQL

本機預設使用 H2。要模擬正式環境時，以 Docker 啟動 PostgreSQL 16，再用 `postgres` profile 啟動後端。

**1. 啟動資料庫**（專案根目錄）

```powershell
docker compose up -d
docker compose ps        # STATUS 為 Up 即可
```

資料存在名為 `pos-db` 的 volume，停止或移除容器後仍會保留。連接埠只綁定 `127.0.0.1`，區域網路上的其他裝置無法連線。

**2. 設定環境變數並啟動後端**（`backend/`，同一個終端機）

```powershell
$env:SPRING_PROFILES_ACTIVE = 'postgres'
$env:DATABASE_PASSWORD = 'pos-local-password'   # 與 docker-compose.yml 相同，僅供本機使用
$bytes = New-Object byte[] 48
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
$env:JWT_SECRET = [Convert]::ToBase64String($bytes)
.\mvnw.cmd spring-boot:run
```

- `postgres` profile 不提供預設的 `JWT_SECRET`，未設定時無法啟動。
- 環境變數只在目前的終端機有效。重新設定 `JWT_SECRET` 後，先前簽發的登入 cookie 會失效，需要重新登入。
- 第一次啟動時，Flyway 會在空資料庫依序套用 V1–V3（`Successfully applied 3 migrations`）；之後啟動會顯示 `Schema "public" is up to date`。

**3. 查詢資料**

```powershell
docker compose exec db psql -U pos -d power_of_sight -c "select version, description, success from flyway_schema_history;"
```

**停止**

```powershell
docker compose stop      # 保留資料
docker compose down -v   # 連同 volume 一起刪除，資料會消失
```
