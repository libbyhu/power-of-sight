# 01 架構與技術選型

## 產品方向（已和作者確認）

- 收藏、記錄書籍、電影、影集與動漫，整體像走進舒適的魔法書房。
- 每人一間個人書房，可以命名、寫介紹，不同種類的作品混放。
- **不建立主題頻道、不要求先分類**。種類、狀態只是篩選。
- 心得、喜好程度、狀態、完成日期都是選填。
- 書房預設私人。

## 整體架構

```
瀏覽器
  │  頁面：http://localhost:3000/zh-TW/room
  │  API ：http://localhost:3000/api/me/entries   ← 同一個網址
  ▼
Next.js（frontend/）
  - 畫面、雙語（next-intl）
  - middleware：沒有登入 cookie 就導到登入頁
  - next.config.js rewrites：/api/* 轉給後端
  ▼
Spring Boot（backend/）
  - Controller → Service → Repository 三層
  - Spring Security：從 cookie 讀 JWT、驗證簽章與期限
  ▼
H2（本機）／ PostgreSQL（正式）
  - Flyway 管理資料表版本
```

### 為什麼用 Next.js 轉址，而不是讓瀏覽器直接呼叫 8080？

如果瀏覽器直接呼叫 `localhost:8080`，那就是「跨網域」：要設定 CORS，cookie 也要設 `SameSite=None; Secure`，本機開發又沒有 HTTPS，會很麻煩。
讓 Next.js 轉址之後，瀏覽器以為所有東西都來自 3000，cookie 用最安全的 `SameSite=Lax` 就行。

## 登入流程

```
1. POST /api/auth/login { email, password }
2. Spring Boot 用 BCrypt 比對密碼
3. 成功 → 簽發 JWT（subject = 會員 id，7 天有效）
4. 回應 Set-Cookie: pos_token=<JWT>; HttpOnly; SameSite=Lax; Path=/
5. 之後每個請求瀏覽器自動帶 cookie
6. Spring Security 驗證 JWT → Controller 用 @AuthenticationPrincipal Jwt 取得會員 id
```

- **httpOnly**：前端 JavaScript 讀不到 token，就算網站被插入惡意腳本（XSS）也偷不走。
- **SameSite=Lax**：其他網站對本站送出 POST 時不會帶上 cookie，用來擋 CSRF。
- **登出**：後端回一個立刻過期的同名 cookie。JWT 本身無法撤銷，這是 stateless 設計的取捨；需要「強制登出所有裝置」時，可以再加 token 版本號或黑名單。

## 技術選型的理由

| 選擇 | 理由 | 取捨 |
|---|---|---|
| Spring Boot 取代 Supabase | 後端邏輯（權限、版本檢查、交易）寫在自己的程式裡，看得見、測得到 | 會員系統要自己做 |
| 自己簽 JWT（HS256） | 只有一個後端，不需要外部登入服務；用 Spring 內建的 Nimbus，不多加套件 | 金鑰要保管好；之後要接 Google 登入時再加 OAuth2 |
| H2 + PostgreSQL | 別人 clone 下來不用裝資料庫就能跑；正式環境用 PostgreSQL | H2 用 PostgreSQL 相容模式，SQL 要寫兩邊都支援的語法 |
| Flyway | 資料表變更有版本紀錄，任何環境都能重建 | 改表要新增 V2、V3 檔案，不能改舊的 |
| 前端不用狀態管理套件 | 頁面之間資料不共用，`useState` + `fetch` 就夠，容易讀 | 之後資料變多可以換 TanStack Query |
